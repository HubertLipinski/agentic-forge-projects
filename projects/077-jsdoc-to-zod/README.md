# JSDoc to Zod Schema Generator

A CLI tool and library that automatically generates Zod schemas from your JavaScript code by parsing JSDoc type annotations. This enables runtime validation based on your existing static type documentation, keeping your validation logic perfectly in sync with your comments.

[![NPM Version](https://img.shields.io/npm/v/jsdoc-to-zod.svg)](https://www.npmjs.com/package/jsdoc-to-zod)
[![License](https://img.shields.io/npm/l/jsdoc-to-zod.svg)](https://github.com/your-username/jsdoc-to-zod/blob/main/LICENSE)

## Description

Stop writing validation logic by hand. With `jsdoc-to-zod`, your JSDoc comments become the single source of truth for both documentation and runtime type-checking. By parsing standard JSDoc tags like `@typedef`, `@param`, and `@property`, this tool generates `zod` schemas that mirror your documented types.

This means you can validate function arguments, API request bodies, and configuration objects with confidence, knowing that your validation rules will never drift out of sync with your documentation.

## Features

-   **Automatic Generation**: Converts JSDoc comments into Zod schemas.
-   **JSDoc Support**: Parses `@param`, `@returns`, `@typedef`, `@property`, and `@type` tags.
-   **Complex Types**: Handles nested objects, arrays (`string[]`, `Array<User>`), and unions (`string|number`).
-   **Type Resolution**: Intelligently resolves custom `@typedef` references across multiple files.
-   **Optional & Default**: Correctly generates `.optional()` and `.default()` modifiers from JSDoc syntax (`[name]`, `[name=value]`).
-   **CLI & API**: Use it as a powerful CLI for your project or programmatically within your build scripts.
-   **Glob Support**: Process single files or entire directories with glob patterns.

## Installation

You can use `jsdoc-to-zod` as a development dependency in your project.

```bash
npm install --save-dev jsdoc-to-zod
```

Or, if you prefer to run it without installing:

```bash
npx jsdoc-to-zod <input...> [options]
```

## Usage

### Command-Line Interface (CLI)

The CLI is the most common way to use the tool. You can point it at your source files, and it will generate a single file containing all the corresponding Zod schemas.

**Basic Usage:**

```bash
jsdoc-to-zod "src/**/*.js" -o "src/schemas.js"
```

This command will:
1. Find all `.js` files in the `src` directory and its subdirectories.
2. Parse the JSDoc comments within them.
3. Generate Zod schemas.
4. Write the combined output to `src/schemas.js`.

**CLI Options:**

| Flag             | Alias | Description                                                               |
| ---------------- | ----- | ------------------------------------------------------------------------- |
| `--output <path>`  | `-o`  | The output file path. If omitted, prints to standard output.              |
| `--help`         | `-h`  | Show the help message.                                                    |
| `--version`      | `-v`  | Show the version number.                                                  |

### Programmatic API

You can also integrate schema generation directly into your own scripts. The `generate` function provides the core functionality.

```javascript
import { generate } from 'jsdoc-to-zod';
import fs from 'node:fs/promises';

async function buildSchemas() {
  const sourceCode = await fs.readFile('./src/types.js', 'utf-8');

  const { zodSchema } = await generate(sourceCode, {
    filePath: './src/types.js'
  });

  await fs.writeFile('./generated/schemas.js', zodSchema);
  console.log('Schemas generated!');
}

buildSchemas();
```

## Examples

### Example 1: Basic Object (`@typedef`)

Given the following JavaScript file `src/types.js`:

```javascript
// src/types.js

/**
 * Represents a user profile.
 * @typedef {object} User
 * @property {string} id - The user's unique ID.
 * @property {string} username - The user's public name.
 * @property {number} [age] - The user's age. Optional.
 * @property {boolean} [isActive=true] - Account status.
 * @property {string|null} email - The user's email address.
 */
```

Run the CLI command:

```bash
npx jsdoc-to-zod src/types.js -o src/user.schema.js
```

The generated file `src/user.schema.js` will contain:

```javascript
/**
 * This file was auto-generated by jsdoc-to-zod.
 * Do not make direct changes to this file.
 */

import { z } from 'zod';

export const User = z.object({
  id: z.string(),
  username: z.string(),
  age: z.number().optional(),
  isActive: z.boolean().default(true),
  email: z.string().nullable(),
});
```

### Example 2: Function Parameters (`@param`)

Given a file `src/api.js` with a documented function:

```javascript
// src/api.js

/**
 * Creates a new product in the database.
 * @param {string} name - The name of the product.
 * @param {number} price - The price of the product.
 * @param {string[]} tags - A list of relevant tags.
 */
export function createProduct(name, price, tags) {
  // ... implementation
}
```

Run the CLI command:

```bash
npx jsdoc-to-zod src/api.js
```

The tool will print the validation schema for the function's parameters to your console:

```javascript
/**
 * This file was auto-generated by jsdoc-to-zod.
 * Do not make direct changes to this file.
 */

import { z } from 'zod';

export const createProductParams = z.object({
  name: z.string(),
  price: z.number(),
  tags: z.string().array(),
});
```

You can now use this schema to validate calls to `createProduct`.
