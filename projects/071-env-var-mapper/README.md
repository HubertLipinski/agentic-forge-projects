# Env Var Mapper

A developer tool that scans a JavaScript/Node.js codebase to generate a comprehensive list of all environment variables being used.

## Description

Env Var Mapper is a command-line tool that helps developers manage environment variables by statically analyzing a project's source code. It scans for all occurrences of `process.env.VAR_NAME` and `process.env['VAR_NAME']`, providing a clear and accurate list of every variable the application depends on.

This is invaluable for:
-   **Auditing:** Quickly see all environment variables used across a large codebase.
-   **Documentation:** Automatically generate an up-to-date `.env.example` file.
-   **Onboarding:** Help new developers set up their local environment without missing variables.
-   **CI/CD:** Ensure that all required variables are configured in deployment environments.

## Features

-   **Recursive Scanning:** Scans directories for `.js` and `.mjs` files.
-   **Static Analysis:** Uses an AST parser (Acorn) for reliable detection of `process.env` access.
-   **Multiple Access Patterns:** Supports both `process.env.VAR` and `process.env['VAR']`.
-   **High Accuracy:** Ignores dynamic access (e.g., `process.env[varName]`) to prevent false positives.
-   **Flexible Output:** Generate a simple list, a detailed report with file locations, JSON, or a `.env.example` file.
-   **Configurable:** Specify target directories and ignore patterns to customize the scan.

## Installation

You can use `env-var-mapper` without installation via `npx`, or install it globally to use it as a standalone command.

**Run with npx (recommended):**
```bash
npx env-var-mapper <directory> [options]
```

**Global Installation:**
```bash
npm install -g env-var-mapper
```

**Clone and Install Locally:**
```bash
git clone https://github.com/your-username/env-var-mapper.git
cd env-var-mapper
npm install
npm link # To use the CLI locally
```

## Usage

The CLI requires a target directory to scan and accepts several options to customize its behavior.

```bash
env-var-mapper <directory> [options]
```

**Arguments:**

-   `<directory>`: (Required) The directory to scan for `.js` and `.mjs` files.

**Options:**

-   `-f, --format <format>`: The output format.
    -   `list`: A simple, sorted list of unique variable names.
    -   `detail`: (Default) A detailed report with file paths and line numbers.
    -   `json`: A machine-readable JSON output.
    -   `env`: Content for a `.env.example` file.
-   `-i, --ignore <pattern>`: Glob patterns for files/directories to ignore. Can be used multiple times.
-   `-o, --output-file <path>`: Write output to a file. If format is `env`, this is used for the output file name.
-   `-h, --help`: Show help.
-   `-v, --version`: Show version number.

## Examples

#### 1. Generate a `.env.example` file for a project

Scan the `src` directory and create a `.env.example` file in the current directory.

**Command:**
```bash
npx env-var-mapper ./src --format env
```

**Output:**
A file named `.env.example` will be created with the following content:

```dotenv
# This file was auto-generated by env-var-mapper on ...
# It contains a list of all environment variables found in the project.
# Add desired default values for development.

API_KEY=
DB_HOST=
DB_NAME=
NODE_ENV=
PORT=
```

#### 2. Get a detailed report of all variable usages

Scan the current directory and print a detailed report to the console.

**Command:**
```bash
npx env-var-mapper .
```

**Output (example):**
```
API_KEY
  at src/api.js:9:21
DB_HOST
  at src/utils/db.js:10:9
NODE_ENV
  at src/api.js:14:22
  at src/api.js:31:52
PORT
  at src/api.js:13:20
  at src/api.js:29:28
```

#### 3. Get a JSON report and save it to a file

Scan the `app` directory, ignoring test files, and save the output as `report.json`.

**Command:**
```bash
npx env-var-mapper ./app --format json --ignore "**/*.test.js" --output-file report.json
```

**Output:**
A file named `report.json` will be created with the following content:

```json
{
  "API_KEY": [
    {
      "file": "app/services/auth.js",
      "line": 5,
      "column": 19
    }
  ],
  "PORT": [
    {
      "file": "app/server.js",
      "line": 12,
      "column": 20
    }
  ]
}
```
